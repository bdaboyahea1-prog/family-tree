# شجرة العائلة

تطبيق ويب ثابت (بلا خادم خاص) لبناء شجرة عائلة يشارك فيها أفراد العائلة بدعوات شخصية.
الواجهة ملفات HTML/CSS/JS عادية تُنشر على GitHub Pages، والبيانات في Supabase (Postgres) محميّة بقواعد الصلاحيات (RLS).

## ما هو مهم أن تعرفه

- **الدخول بدعوة فقط:** كل دعوة مرتبطة ببريد إلكتروني واحد ولمرة واحدة، أو **رابط بلا بريد لشخص واحد** يصنعه المدير (يعمل مرة واحدة ويدخل به صاحبه بدور «قارئ»؛ `supabase/013`). لا أحد من خارج الشجرة يرى أي بيانات.
- **المفتاح في `js/config.js` عام بطبيعته** (publishable key): الحماية الحقيقية في قواعد قاعدة البيانات، لا في إخفائه.
- **لا تضع هنا بيانات شخصية** (هواتف، بريد، أسماء حقيقية): تُخزَّن داخل التطبيق في قاعدة البيانات ولا يراها إلا الأعضاء. يمنع الاختبار `tests/about.test.mjs` ذلك.

## تشغيل نسخة محلية

```bash
python -m http.server 8080 --bind 127.0.0.1
```

ثم افتح `http://localhost:8080`. وللتجربة دون تسجيل دخول: `#/demo`، `#/demo-edit`، `#/demo-admin` (بيانات وهمية).

## الصفحة العامة وطلبات الانضمام

- الصفحة الأولى التي يراها أي زائر (`index.html` + `showLanding` في `js/app.js`): نص تعريفي ثابت تقرؤه محركات البحث، والجد الأكبر وأبناؤه المباشرون فقط (الاسم والسنوات). الباقي رسم شكلي مموَّه **لا يحمل أي بيانات**، والبيانات الحقيقية الوحيدة التي تخرج من قاعدة البيانات هي ما يعيده `public_teaser()` (`supabase/010`).
- يفعّلها مدير الشجرة من **الإعدادات ← الصفحة العامة**، وهي متوقفة افتراضيًا. الأحياء لا يظهرون فيها إلا إن سمح المدير.
- طلب الانضمام **بلا حساب**: استمارة (المدينة والهاتف والبريد ووثيقة الإثبات كلها اختيارية؛ الوثيقة صورة أو PDF حتى 5 ميغابايت في حاوية خاصة `join-docs`)، وتُعطى الزائر **رقم متابعة** سرّيًا يكفيه وحده لمعرفة حالة طلبه. إن لم يكتب بريدًا يكتبه بعد الموافقة في صفحة المتابعة فتُنشأ له الدعوة (`supabase/012`). لا يرى الوثيقة إلا المدير، وتُحذف بعد القرار. تظهر الطلبات للمدير في **الوارد ← طلبات الانضمام**؛ عند القبول تُنشأ دعوة مرتبطة ببريد الزائر (يرسلها المدير بواتساب أو بريد، وتظهر للزائر في صفحة المتابعة ليُنشئ حسابه). وفي قاعدة البيانات حدود للإزعاج (`supabase/011`).
- لمعاينة الصفحة بدون قاعدة بيانات: `#/demo-landing`.

## الاختبارات

```bash
for t in tests/*.test.mjs; do node "$t"; done
```

## قاعدة البيانات (Supabase)

شغّل الملفات في **SQL Editor** بهذا الترتيب مرة واحدة لكل مشروع جديد:

`supabase/schema.sql` ثم `002_branch_permissions.sql` ثم `003_branch_levels_and_email_invites.sql` ثم `004_undo_and_photos.sql` ثم `005_fix_revert.sql` ثم `006_places.sql` ثم `007_requests_reports_comments.sql` ثم `008_contacts_and_about.sql` ثم `009_female_cards.sql` ثم `010_public_page_and_join.sql` ثم `011_join_without_account.sql` ثم `012_optional_fields.sql` ثم `013_open_invites.sql` ثم `014_nickname.sql` ثم `015_looks.sql`.

ملفات `*_test.sql` اختبارات ذاتية: تنشئ بيانات وهمية وتعرض تقريرًا ثم تتراجع عن كل شيء (الخطأ الأحمر في آخرها متوقع). و`diag_history.sql` استعلام قراءة فقط لتشخيص السجل.

بعد النشر اضبط في Supabase: **Authentication ← URL Configuration** فيكون *Site URL* رابط الموقع، وأضف الرابط نفسه إلى *Redirect URLs*.

## الهيكل

| المسار | المحتوى |
|---|---|
| `index.html`, `css/style.css` | الصفحة والتنسيق |
| `js/app.js` | التطبيق: الدخول، النوافذ، اللوحات، الإعدادات |
| `js/tree.js`, `js/chart.js` | تخطيط الشجرة (عمودية، أفقية، مروحة، طبيعية) ورسمها |
| `js/permissions.js` | قواعد الصلاحيات في الواجهة (تقابلها قواعد قاعدة البيانات) |
| `js/exports.js`, `js/xlsx.js` | تصدير Excel (ملف حقيقي بلا مكتبات) |
| `js/places-*.js` | قوائم الدول والمحافظات والمدن |
| `supabase/` | هيكل قاعدة البيانات والاختبارات |
| `tests/` | اختبارات Node |
